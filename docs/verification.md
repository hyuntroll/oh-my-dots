## Practical limits

- Original cloud planning/model/memory/scheduler/tool-policy source is unavailable in the shipped client. The local adapter is independently authored.
- Original email/calendar connections and account cookies are not reconstructed; unavailable features are labelled accordingly.
- This local version uses one shared Linux computer, with separate file-tool directories per Dot. It does not provision a separate VM per profile.
- Model capability and account access remain provider-dependent. The default free model required the bounded structured tool-loop adaptation. Actual screenshot bytes can be attached; autonomous visual reasoning requires a model that accepts images. A successful terminal launch does not prove the model can interpret arbitrary pixels.
- Source Motion springs are approximated with CSS; onboarding ring animation is not a pixel-identical recreation of the original Three.js choreography.
- Original live account-gated Dots was not exercised. Runtime results here establish the new local app's behavior, not original cloud availability.

During desktop image building the host disk filled, causing Docker I/O failures. Regenerable npm/pip download cache and only this investigation's identified build-cache records were reclaimed; existing images and volumes were retained. After recovery approximately4GiB was available and the actual service was healthy. The checked-in startup path now reuses an existing image to avoid unnecessary package rebuilds.
