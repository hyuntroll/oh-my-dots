# Computer UI 변경 — 2026-10-05

제공된 http://127.0.0.1:8768/computer-reference-board.html 의 실제 캡처를 확인하고 구현했습니다. 자료의 사진·제품 캐릭터를 앱에 복사하지 않았으며 MyDot 캐릭터와 Dock SVG 아이콘은 새로 작성했습니다.

| 참고 | 반영한 요소 |
| --- | --- |
| R22 | 다크 채팅·Computer 분할 배치, 세로 구분선, 컴퓨터를 우선하는 폭 배분 |
| R21 / R25 | 따뜻한 원격 데스크톱, Chromium 시작 페이지의 실제 시계, 겹치는 앱 창, 작은 반투명 Dock |
| R04 / R05 / R23 | 화면 밖의 제어권 바, USER 상태의 분홍 테두리·Return control 강조 |
| R24 / R12 | 모바일 Computer 탭, 앱·텍스트·키보드 도구를 화면 밖에 배치 |

웹 테마는 `apps/web/app/computer-workspace.css`의 색상 토큰으로 관리합니다. 실제 Linux Dock은 `computer/desktop/dot_dock.py`, `dock.css`, `icons/`이며, 시작 페이지는 `start.html`입니다. Openbox 창 테마와 터미널 설정도 실제 앱에 적용했습니다. X11 compositor와 실제 GTK 배경 창으로 Dock 투명도를 표시합니다.

시작 페이지는 KST 시각·날짜와 공개 Example/IANA 페이지 및 실제 결과 폴더로 연결됩니다. Dock은 Browser/Terminal/Files만 표시하며 실행·기존 창 전환·호버 확대·실행 중 표시를 유지합니다. Computer의 입력은 기존 소유자/epoch API를 통과합니다. 전체 화면은 브라우저가 지원하는 Fullscreen API를 사용합니다.

## 검증

- TypeScript 검사와 Next production build 통과.
- 컴퓨터 Docker image build, Compose config, 셸 스크립트 문법 검사 통과.
- Ruff와 기존 제어권·FIFO·셸 테스트 17개 통과.
- 실제 앱에서 Take over 후 USER 상태 테두리·제어 바와 입력 도구 활성화를 확인.
- 실제 화면의 Dock Terminal 클릭 → 터미널 실행. 텍스트 입력 도구와 키보드 Enter로 `echo 'MyDot Dock UI ready'`를 입력해 출력 확인.
- 실제 화면의 Dock Files 클릭 → `/workspace/artifacts` 파일 관리자와 기존 결과 폴더 확인.
- Return control에서 실제 Codex가 새 홈 페이지·터미널 출력·파일 관리자 화면을 분석하고 AGENT로 반환한 것을 확인.
- 390×844 viewport에서 모바일 대화/컴퓨터 전환, Take over 강조, 텍스트 입력 팝업을 확인. 초기 연결 중 임시 상태 이후 정상 연결되었으며 최종 브라우저 콘솔 오류 0건.
- 최종 모바일 DOM 치수: viewport 390px, 페이지 폭 390px, 입력 도구 버튼 5개 각각 44px. 최종 API 재기동 후 브라우저 재연결에서도 서버 traceback 0건.
- 전체 화면 진입·종료 확인. 에뮬레이션 viewport와 OS 전체 화면의 크기가 달라 전체 화면 치수 일치까지 검증한 것은 아닙니다.
- UI 증거는 `output/ui-2026-10-05/`에 저장합니다. 모바일은 브라우저 viewport로 확인하며 실제 휴대폰의 가상 키보드·터치 정밀도 검증은 포함하지 않습니다.

브라우저 재연결 시 WebSocket 정리 중 이미 종료된 연결이 다시 close되어 서버에 남던 예외 로그도 처리했습니다.

앱은 http://localhost:3080 에서 실행합니다. 원격 GUI·PostgreSQL·별도 셸·gateway는 Docker, API/web은 로컬 프로세스입니다. 이 변경에는 신규 OpenAI 키 발급이나 API 실요청 검증이 포함되지 않습니다.
