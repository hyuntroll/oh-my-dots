# 사용자 원격 조작 중 멈춤 복구

사용자 제어 상태에서 입력 응답이 늦어지면, 기존 코드는 모든 마우스 이동을 하나의 Promise 체인에 쌓았습니다. 뒤의 앱 실행과 키 해제도 이 체인을 기다렸고, 제어권을 변경해도 체인이 남았습니다. 실제 브라우저에서 입력 요청을 2초 지연시키고 80회 드래그한 뒤 Terminal을 눌러 재현했습니다. 화면은 실시간 연결로 표시되지만 Terminal 요청은 전송되지 않았습니다.

## 변경

- 연속 드래그는 최신 좌표로 합칩니다. 스크롤과 연속 텍스트도 범위 안에서 합치며, 클릭·키 해제·앱 실행 순서는 유지합니다.
- 소유자/epoch/연결 상태가 바뀌면 대기 입력을 폐기하고 진행 중 요청을 중단합니다. 전송 직전에도 소유권과 epoch를 다시 확인합니다.
- 입력 실패 시 불확실한 입력을 재실행하지 않고 키와 마우스 버튼을 해제합니다. 사용자 연결 복구 시에도 먼저 해제를 요청합니다.
- 일반 API 요청은 응답 본문까지 10초 제한을 적용합니다. Return control은 기존 서버의 화면 분석 제한을 고려해 115초로 별도 설정합니다.
- 화면 연결 실패는 자동 재시도하고, 온라인 복귀/탭 복귀 및 상단 다시 연결 버튼으로 연결과 입력 대기를 초기화합니다.
- 상태 갱신은 한 번에 하나만 실행합니다. 제어권 변경 응답은 바로 반영하고, 앞서 시작한 갱신이 새 제어권을 덮어쓰지 않게 합니다.
- 키 해제 검사 직후 제어권이 바뀌는 경쟁 상황은 409로 반환합니다. 기존에는 내부 어댑터의 409가 처리되지 않아 서버 500 오류로 바뀌었습니다. 입력 연결 시간 초과도 복구 안내와 함께 503으로 반환합니다.

## 검증

- `node --test tests/web-recovery.test.mjs`: 6개 통과. 드래그 병합과 순서, 텍스트 순서, 이전 epoch 폐기, 중단 후 새 입력, 실패 후 해제, 연결/응답 본문 제한을 확인합니다. Node 24 이상을 사용합니다.
- `.venv/bin/pytest -q`: 기존 17개와 키 해제 경쟁/입력 연결 시간 초과 회귀 테스트 2개, 총 19개 통과.
- `npm run build --prefix apps/web`: TypeScript 검사 및 프로덕션 빌드 통과.
- 실제 localhost:3080 브라우저에서 2초 지연/80회 드래그가 down→move→up→launch 4개 입력으로 처리됐습니다. Terminal 실행 응답은 버튼 클릭 후 약 7.5초에 완료됐습니다.
- 첫 입력 응답을 14초 지연시키면 10초 제한으로 종료되고, 자동 화면 재연결 뒤 다음 Terminal 입력이 성공했습니다. 재검증에서는 연결 복구가 약 0.35초 걸렸습니다. 앞선 시도에서는 15초 관찰 구간 안에 재연결이 끝나지 않아 수동 재연결도 확인했습니다.
- 네트워크 지연 주입을 하지 않은 별도 브라우저에서 Return control → Take over → Terminal 실행을 확인했습니다. API 최종 반영 후 연결이 자동 복구됐고, 터미널을 클릭해 초점을 맞춘 뒤 원격 텍스트 입력과 Enter로 `echo 'MyDot input recovered'`를 실행했습니다. 실제 화면에 `MyDot input recovered`가 출력됐습니다(final-input.png). 앱 실행 API 응답은 프로세스 시작까지를 뜻하므로, 텍스트 검증은 창이 열린 것을 확인한 뒤 수행했습니다.
- 증거: `output/playwright/freeze-recovery/`의 before.json, after-drag.json, after-auto-recovery.json과 화면 캡처. 네트워크 지연 재현의 결과이며 모든 실제 네트워크/데스크톱 장애를 재현한 것은 아닙니다.
