# 실시간 실행과 사용량

OhMyDots는 모델 제공자의 이벤트를 서버에서 공통 형식으로 변환해 기존 WebSocket으로 전달합니다.

| 이벤트 | 의미 |
| --- | --- |
| `tool.started` / `tool.completed` / `tool.failed` / `tool.cancelled` | 호출별 시작·종료와 명령, 출력, 소요 시간 |
| `run.activity` | 요청 확인, 실제 도구 실행, 실행 결과 확인 |
| `message.updated` | 동일 item_id의 현재 전체 텍스트 |
| `run.usage` | 해당 Run의 누적 입력·출력·캐시 토큰 |
| `run.changed` | 대기·실행·사용자 응답 대기·완료·실패·취소 |

텍스트는 최대 10Hz로 저장하며 완료 이벤트에서 남은 내용을 반영합니다. 각 스냅샷에 증가하는 이벤트 sequence가 있어 재연결·조회·WebSocket 간 중복이나 순서 역전을 처리할 수 있습니다. 대화 조회에는 종류별 최신 실행 이벤트와 도구 호출 기록 전체가 포함됩니다. 화면에는 사용자에게 보여줄 메시지만 전달하며 구조화된 결과 JSON이나 내부 추론 이벤트를 출력하지 않습니다.

대화 안의 작업 기록은 실행 중 자동으로 펼쳐지고 완료 후 접힙니다. 사용자가 직접 열거나 닫은 상태는 유지합니다. 각 도구는 고유 `call_id`로 시작·종료를 연결하며, 종료 이벤트에 `duration_ms`를 기록합니다. 이전 기록은 이벤트 시각으로 소요 시간을 계산합니다. 셸 명령·작업 경로와 stdout/stderr는 상세 카드에서 확인할 수 있습니다. 명령과 각 출력은 8,192자까지 저장하고 생략 여부를 표시합니다. 이미지 데이터와 GUI 입력 텍스트는 기록에 복제하지 않습니다. 셸 출력은 명령이 종료된 뒤 표시됩니다.

스트리밍 텍스트는 임시 출력입니다. Run의 성공은 제공자의 완료 상태, 구조화된 Outcome과 결과 파일의 재읽기 확인을 거쳐 별도로 판정합니다. 최종 메시지를 저장한 뒤 완료 상태를 전달합니다. 취소 시 제공자의 실행을 종료하고 기존 셸 취소 절차를 수행합니다.

Codex는 기존 로그인으로 로컬 app-server를 실행합니다. 임시 스레드, 읽기 전용 호스트 샌드박스, 기존 호스트 도구 비활성화 설정과 OhMyDots MCP만 사용합니다. 인증 파일을 읽거나 복사하지 않습니다. OpenAI API는 Agents SDK의 `Runner.run_streamed` 이벤트를 사용합니다.

사용량은 모델이 보고한 값입니다. 같은 Run에 여러 누적 보고가 있어도 마지막 보고만 집계합니다. 도구 실패·취소 등으로 사용량이 보고되지 않은 작업은 집계에 포함되지 않을 수 있습니다. 계정 잔여 한도, 구독 사용률이나 청구 금액을 제공하지 않습니다.

참고: [공식 Codex app-server 문서](https://learn.chatgpt.com/docs/app-server).

## 검증

- Python 테스트: 구조화 JSON/문자 이스케이프 처리, 완료 전 출력, 최종 결과 판정, 프로세스 종료, 누적 사용량 중복 방지, OpenAI SDK 이벤트 변환.
- 웹 테스트: 이전 스냅샷과 재연결 이벤트 중복 제거, 서로 다른 Run의 상태 분리.
- 실제 Codex: sleep 5 → 파일 작성 → 재읽기 → 완료. 23개 메시지 스냅샷을 기록하고 최초 출력은 완료 21.23초 전에 도착.
- 실제 브라우저: 작업 문구, 사용량, 실행 중 새로고침 복원, 취소 후 진행 표시 종료 확인. 취소한 sleep 30 프로세스는 남아 있지 않음.
- OpenAI API 실요청은 키가 없어 수행하지 않았으며 모의 SDK 스트림으로 검증.

로컬 증거: `output/execution/live-report.json`, `progress.png`, `usage.png`, `cancelled.png`.

### 작업 기록 UI 검증

- 실제 Codex 셸 명령(12초) → 파일 작성 → 파일 확인: 세 호출의 아이콘, 시간과 셸 stdout 상세를 브라우저에서 확인.
- 명령 실행 중 새로고침: 호출 기록과 경과 시간 복원. 완료 후 자동 접기, 수동 펼치기와 상세 출력 확인.
- 실제 sleep 30 작업 취소: `실행 취소됨`과 확정 소요 시간 표시. 새로고침 후 완료·취소 기록 복원, 셸 프로세스 잔존 없음.
- 호출 ID에 따른 동시 호출 연결, 역순·중복 재생, 출력 길이 제한, 민감한 GUI 입력 제외, 반복 실패 마지막 출력 보존 테스트.

로컬 증거: `output/execution/activity-report.json`, `activity-running.png`, `activity-complete.png`, `activity-cancelled.png`.

## 질문과 선택지

`ask_user`는 `question`과 선택적인 2~4개 문자열 `options`, 0부터 시작하는 `recommended_index`를 받습니다. 선택지가 없으면 직접 입력만 표시합니다. `run.question`에 고유 `question_id`와 선택지를 저장하고 대화 조회에서 최신 질문을 복원합니다.

채팅 하단의 질문 카드는 추천 항목을 미리 선택하지만 자동 제출하지 않습니다. 사용자는 다른 항목이나 직접 입력을 선택해 **답변 제출**로 이어갑니다. 접기를 누르면 대기 상태를 유지하고 입력창 위 **질문에 답하기**에서 다시 펼칠 수 있습니다. 일반 입력창으로도 답할 수 있습니다. `/runs/{id}/answer`는 질문 ID가 현재 대기 중인 질문과 일치해야 하며, 지난 질문의 중복 제출이나 공백 답변은 거절합니다. 질문 대기는 기존 Run과 FIFO 순서를 유지합니다.

검증: 실제 Codex가 추천 항목을 포함한 3개 선택지를 전달하고, 브라우저에서 추천 기본 선택·다른 선택지·직접 입력·빈 답변 제출 방지·새로고침 복원·닫기와 다시 열기를 확인했습니다. 직접 입력한 답변을 제출한 뒤 동일 Run이 완료되었습니다. 회귀 테스트는 이전 질문 ID 재전송 거부, 사용자 답변 전 FIFO 대기, 질문 스냅샷 순서 역전을 포함합니다. 로컬 화면 증거는 `output/execution/question-options.png`, `question-custom.png`입니다.

### 하단 질문 카드와 Dock 갱신

질문 카드를 메시지 입력창 바로 위에 배치하고 배경 흐림과 모달 포커스 제한을 제거했습니다. 추천·다른 선택·직접 입력 및 제출 규칙은 유지합니다. 참고 이미지의 얇은 구분선을 적용하고 긴 질문은 카드 안에서 스크롤합니다.

Dock은 제공된 11.69초 영상의 움직임을 참고해 커서 거리 기반 인접 아이콘 확대, 아래쪽 기준선에서의 상승, 클릭 눌림과 감쇠 바운스를 적용했습니다. 아이콘의 고정 클릭 영역과 실제 앱 실행·기존 창 전환을 유지하며 낮은 반투명 배경 위로 아이콘이 올라옵니다. 현재 실행 환경은 사용자 폴더의 Dock 프로세스만 교체해 반영했으며, 다음 컨테이너 생성에도 반영되도록 `ohmydot-computer:dev` 이미지 빌드를 완료했습니다. 기존 컨테이너는 재생성하지 않았습니다.

검증: 웹 테스트 11개와 production 빌드 통과. 실제 Dock 클릭으로 터미널 실행 및 확대 표시 확인, 하단 질문 카드 새로고침 복원과 선택 답변 제출 확인. 화면 증거: `output/execution/dock-wave.png`, `question-inline.png`.
