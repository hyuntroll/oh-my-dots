`output/live-control.json`:

- AGENT 소유권 중 사용자 입력 409.
- USER 소유권 중 Agent 입력 409, 사용자 GUI 앱 실행 정상.
- Take over 이전에 시작한 실제 셸 작업이 인계 후에도 정상 종료.
- Return control에서 실제 Codex가 새 PNG 화면을 분석한 뒤 AGENT로 반환.
- 이전 사용자 epoch 입력 409.
- 셸 취소 시 프로세스 그룹 종료.

`output/live-resume.json`:

- 실제 Codex `ask_user` 답변을 같은 Run으로 처리.
- USER 소유권 동안 GUI 요청이 `WAITING_USER / CONTROL`에서 대기.
- 사용자가 GUI 주소창으로 IANA 공개 페이지에 이동.
- 반환 후 새 화면으로 재계획하고 `handoff/current-page.txt`에 현재 페이지 제목을 저장·재읽기하여 COMPLETED.
- 이 사례의 Take over API 응답: 11.3ms. 부하 테스트 수치는 아닙니다.

`output/live-restart.json`:

- 실제 Codex Run 대기 중 로컬 API를 강제 종료하고 재시작.
- 해당 Run이 `FAILED / SERVER_RESTARTED`로 복구되고 재실행되지 않음.
- 같은 Run의 실제 셸 프로세스 그룹을 복구 시 취소. 실패 뒤 결과 파일이 생성되지 않음.

`output/live-cancel.json`:

- 실제 Codex Run과 같은 Run의 동시 셸 작업을 사용자 Cancel API로 취소.
- Run이 CANCELLED, 셸 프로세스 그룹 종료, 후속 파일이 생성되지 않음.

셸 컨테이너에서 GUI 게이트웨이 bootstrap 접근은 403, 게이트웨이 헤더 없는 직접 API bootstrap도 403입니다. VNC 서버 자체는 view-only로 설정했고 실제 사용자 입력은 별도 API로 처리합니다. 임의 RFB 패킷을 이용한 우회 테스트는 별도로 수행하지 않았습니다.

## 남아 있는 범위와 제한

- **OpenAI API 실요청과 신규 API 키 발급은 아직 미검증**입니다. 안전한 발급 폼에서 조직·프로젝트와 로컬 저장 위치 확인이 필요합니다. 현재 실제 실행 증거는 Codex Auth에 해당합니다.
- 기존 Codex 로그인 사용은 검증했습니다. 새 계정의 기기 코드 로그인 완료는 사용자 상호작용이 필요합니다.
- 화면/Activity는 실제 WebSocket 스트림입니다. 대화 응답은 구조화된 완료 판정 후 표시하며 토큰 단위 출력은 포함하지 않습니다.
- 5fps, 화면 반영 2초 목표에 대한 별도 계측과 장시간 부하 검증은 수행하지 않았습니다.
- 로컬 단일 사용자/백엔드 단일 프로세스 데모입니다. 외부 사용자 배포, 멀티 워커, 자동 보존기간 삭제는 포함하지 않습니다. 현재 computer/shell/PostgreSQL/gateway는 Docker, API/web은 로컬 production 프로세스입니다. computer/shell에는 Compose resource limit을 적용했습니다. API/web의 resource limit과 컨테이너 구성은 이미지 빌드까지 검증했으며 전체 컨테이너 실행은 별도 검증이 필요합니다.
