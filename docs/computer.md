# Actual local computer

`computer/compose.yaml` defines the isolated `dots-reconstructed` Compose project. Only port3480 on loopback is published. The container is a separate Linux desktop (Xvfb1280×960, Openbox, Chromium, terminal and file manager), with a FastAPI adapter. `.data/workspaces` is its sole host work directory mount. The container runs as a non-root user, drops capabilities and uses no-new-privileges, memory/CPU/PID limits. Chromium's sandbox flag applies inside this container; it does not change the host browser configuration.

The computer is an independent adapter, not recovered cloud source. This version uses one shared Linux desktop for all local Dots; each Dot has its own file-tool directory, but computer control can see the mounted workspace tree. It does not reproduce a separate cloud VM per Dot. Screen frames come from `mss` capture of the actual X display; `/health` also checks that the display answers. The initial HTML page is an actual browser window on that desktop, not a replacement screenshot. If the service or display is unavailable, the application shows a disconnected state.

The local backend proxies `/api/computer/status`, `/start`, `/stop`, `/control`, `/input`, `/screenshot`, `/stream`. A random token stored mode600 in `.data/computer.token` authenticates the server-to-container calls and is never sent to the web frontend. `computer_url` accepts loopback HTTP only. Host and same-site checks also apply to the proxy.

Every ownership transfer advances an epoch and releases held keys/buttons. Inputs require the current owner and epoch. Manual input is serialized by the UI; leaving the screen releases held input. Dot actions pass the same runtime approval boundary as file writes and are rejected while the user owns the computer. Status and screenshots are read-only tools. The model receives actual screenshots as image attachments when the inference adapter supports that model's image input; a text-only model cannot inspect pixels reliably.

The Grok reconstructed runtime now uses this same desktop through its original Computer/Screenshot tools and computerUse Task. Its computer instructions remain in the Grok source. A task-scoped private bridge validates actions and serializes desktop ownership; the original human approval/state recheck and the local Dots approval both apply. The unavailable cloud classifier is represented explicitly as requiring manual review, never an automatic allow. Only sanitized, read-only browser tab metadata is exposed to the original review probe; the CDP endpoint is loopback inside the container and is not published. `request_box_help` transfers ownership to the user; explicit return from the original viewer resumes the original Grok handoff with a new screenshot. See [Grok integration evidence](grok-integration.md).

`npm run computer:start` builds/starts only this Compose project, reusing the installed image on subsequent starts. Use `npm run computer:start -- --rebuild` after changing image packages. The two local adapter source files are mounted read-only, so adapter repairs do not require reinstalling desktop packages. Startup removes only its own stale display99 lock/socket inside the container and fails promptly if X cannot start; this handles Docker/container restarts after a crash. `npm run computer:stop` removes its container/network but retains host files. Docker Desktop and several GB of free host disk space are required. A Docker daemon failure is surfaced instead of starting a simulated computer. Contract tests exercise the proxy with a controlled service; a running-desktop validation is recorded separately in `verification.md`.
